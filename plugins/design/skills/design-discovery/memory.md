# Design Discovery Memory

Learnings from past discovery sessions. Read this before starting any session.

## Reading Memory

Before starting, scan entries for:
- Features in the same area of the product
- Similar feature types (multi-role, data-heavy, workflow-based, form-based)
- Domain patterns that recur across features
- User corrections that revealed non-obvious rules
- Approaches that worked well or poorly for specific feature shapes

## Writing to Memory

After every completed discovery, evaluate whether the session produced a learning worth capturing. Write an entry if:
- A user correction revealed a non-obvious domain rule that would apply to future features
- A discovery approach (A/B/C/D) worked particularly well or poorly for a feature shape
- The team missed something important that was only caught late in the process
- A pattern emerged about how this product's users think or work
- A product-wide convention was established that future features should follow

Do NOT write:
- Feature-specific details that only matter for that one feature
- Obvious rules already captured in the feature's conventions.md
- Restating what is in requirements

Only capture what would change how you approach the NEXT discovery session.

## Entry Format

```markdown
## [Date] -- [One-line summary]
**Feature area**: [area of the product]
**What we learned**: [the insight, one or two sentences]
**Why it matters**: [how this changes future discovery approach]
```
